## Overall Impression

This is not AI slop in the "generic purple SaaS template" sense — the product has a real, deliberate identity (warm serif + humanist sans, two-register palette, bespoke illustration, honest empty states) and the code mostly executes it. The gap is discipline, not identity: the exact signature interaction details DESIGN.md calls out by name (tactile press feedback, earned shadows, the stone/slate split, muted semantic color) are the parts that slipped in the actual implementation. The single biggest opportunity is closing that gap — it's cheap, mechanical work (a shared Button component, a few `slate-*`→`stone-*` renames, wiring `STAGE_BADGE` to existing CSS variables) that would make the interface actually as considered as it claims to be, rather than a bigger creative overhaul.

## What's Working

1. **Honest, non-fabricated empty/placeholder states** — `NoIllustration` explicitly labels missing exercise demonstrations ("Démonstration à venir") instead of faking a generic pictogram, directly honoring PRODUCT.md's "never fabricate" rule.
2. **Motion discipline is genuinely engineered, not decorative** — `prefers-reduced-motion` handling in `globals.css` uses `animation-fill-mode: forwards` specifically to avoid a "garbled triple exposure" on the exercise cross-fade, with a comment explaining why. Real care, not boilerplate.

4. **The deterministic scan came back almost clean** — zero em-dash-as-flourish beyond real prose lapses, zero buzzwords, zero emoji regressions, zero unlabeled icon-only controls. The "no AI slop" goal is already mostly met at the pattern level; what's left is finish-work, detailed below.

## Priority Issues

**[P1] Interactive hover-lift shadow applied to non-clickable containers, systemically**
- **Where:** Whole alert `<section>`s on the dashboard home (`app/dashboard/page.tsx:117,154`), the séance-creation `<form>` (`app/dashboard/seances/page.tsx:111`), both facturation `<section>`s (`app/dashboard/facturation/page.tsx:54,90`), and the template séance cards (`components/SeancesTabs.tsx:274-296,341-363`) — plain `<div>`s carrying the identical `CARD_HOVER` treatment as the "mine" cards two lines away that ARE real `<Link>`s.
- **Why it matters:** A kiné hovering a template card gets the exact same "this is clickable" signal as hovering a card that navigates, then nothing happens on click. It also inverts DESIGN.md's own Earned-Shadow Rule — the shadow fires on hover over static content, which is decoration triggered by the wrong gesture.
- **Fix:** Either make the whole template card a real `<Link>` to a detail view (with "Dupliquer" as a secondary nested action), or strip the lift/shadow from containers whose only actionable element is a nested button.
- **Suggested command:** `/impeccable polish`

**[P1] The documented signature tactile press feedback (`active:scale-95`) is absent from every primary button on all 4 surfaces**
- **Where:** "Créer et composer", "+ Ajouter un nouvel exercice"/"Créer", "Valider"/"Mettre à jour", "Activer les paiements", "Dupliquer" — repo-wide grep for `active:scale` returns 6 files, none of them these 4 surfaces or their components.
- **Why it matters:** DESIGN.md names this as *the* signature interaction detail ("a physical, tactile press rather than a color-only change"). It's missing from exactly the buttons a working professional clicks dozens of times a day.
- **Fix:** Add `active:scale-95` to the shared button classes; worth extracting a shared `Button` component so this stops being re-litigated per surface.
- **Suggested command:** `/impeccable polish`

**[P2] A third neutral gray scale (slate) is leaking into the stone/paper clinical register**
- **Where:** `components/ExerciseVideoUpload.tsx:127,131,135,142` (`border-slate-300`, `text-slate-700`, `hover:bg-slate-50`, `text-slate-400`) and `components/ExerciseIllustration.tsx:79,81` (`text-slate-300`/`text-slate-400`) — both rendered exclusively inside the exercises board's stone/paper surface.
- **Why it matters:** DESIGN.md's Two-Register Rule is explicit: "Never mix a stone-neutral card into a slate-neutral page or vice versa." This is that exact violation, inside the component library used constantly while building content.
- **Fix:** Replace `slate-*` with the equivalent `stone-*` tokens in both files.
- **Suggested command:** `/impeccable polish`

**[P2] Séance stage badges use raw saturated Tailwind colors, bypassing the documented muted semantic palette**
- **Where:** `components/SeancesTabs.tsx:34-39` (`STAGE_BADGE`) uses `bg-red-100 text-red-700`, `bg-orange-100`, `bg-amber-100`, `bg-green-100` — full-saturation defaults, not the dusty `--grade-green-bg #e1e8d9` / `--grade-yellow-bg #f1e3c2` / `--grade-red-bg #ead1cb` tokens already defined in `globals.css:40-45` for exactly this purpose.
- **Why it matters:** DESIGN.md requires clinical-severity color to stay "muted/dusty... never a saturated alarm red." This is a second, uncoordinated semantic-color system competing with the single sparse blue accent the whole design is built around.
- **Fix:** Map `STAGE_BADGE` onto the existing `--grade-*` variables.
- **Suggested command:** `/impeccable polish`

**[P2] Em-dashes appear in real, visible French copy on 4 of the 4 surfaces**
- **Where:** `app/dashboard/page.tsx:124` (alert-card body), `app/dashboard/facturation/page.tsx:95` (billing explainer paragraph), `components/ExerciseLibraryGrid.tsx:230` (form heading) and `:325` (toggle-button label). A fifth instance (`SeancesTabs.tsx:93`) is a `??"—"` missing-value placeholder, a different and acceptable use.
- **Why it matters:** the em-dash is a well-known LLM writing tell; in French clinical UI copy it also reads as an odd register shift mid-sentence.
- **Fix:** Rewrite each as two sentences, a comma, or a colon — plain French punctuation.
- **Suggested command:** `/impeccable clarify`

**[P2] No pending/loading state on any server-action submit**
- **Where:** "Créer et composer", "Créer", "Dupliquer", "Valider"/"Mettre à jour", "Activer les paiements" all submit via `<form action={...}>` with a plain `<button type="submit">` — no `useFormStatus`, no disabled state, no spinner anywhere across the 4 surfaces.
- **Why it matters:** on the clinic wifi this tool actually runs on, a kiné who sees nothing happen after clicking "Dupliquer" has every reason to click again — with no idempotency signal, that's an invitation to create duplicate séances/exercises.
- **Fix:** A small `SubmitButton` wrapper using `useFormStatus()` to disable and show busy state during the round-trip.
- **Suggested command:** `/impeccable harden`

**[P2] "Séances prévues" tab label doesn't match the "modèle"/template concept it actually holds**
- **Where:** `components/SeancesTabs.tsx:194` labels the shared platform-template tab "Séances prévues", while the body copy two lines away calls the same content "modèle" ("Dupliquez-en une pour en faire votre propre version modifiable").
- **Why it matters:** a first-time kiné scanning tab labels for "where's the starter content I can copy" has no lexical hook to "Séances prévues" meaning that — a real discoverability cost on a flow PRODUCT.md names as a core capability.
- **Fix:** Rename the tab to something that echoes "modèle"/"bibliothèque" language used in the surrounding copy.
- **Suggested command:** `/impeccable clarify`

## Persona Red Flags

**Alex (power user, dozens of patients/day):** the missing pending-state is the concrete daily-friction item — on a spotty connection, a double-submitted "Dupliquer" produces cleanup work with no toast/feedback distinguishing "it worked" from "did I press it." The 4-color stage-badge system also fights the sparse-accent training Alex builds up everywhere else — every séance card now has a second, unrelated color signal competing with the one blue accent meant to mean "the important thing."

**Sam (accessibility-relevant):** secondary/meta text is set in `stone-400`/`slate-400` at `text-xs` (exercise counts, video-upload hints) — sits under WCAG AA's 4.5:1 threshold for small text, a real risk for low-vision users on informational-but-not-decorative copy. The exercise card's three-dot menu carries a generic `aria-label="Options"` with no per-exercise disambiguation — a screen-reader user tabbing through a grid of a dozen cards hears "Options button" a dozen times with no way to tell which card each belongs to.

**Busy first-time clinician on the séances board:** see the "Séances prévues" naming issue above — the tab meant to hold reusable starter content has no lexical connection to how the rest of the page describes that same content.

## Minor Observations

- Two distinct near-identical off-white hex values coexist for the same conceptual background: `bg-[#faf7f2]` (`app/dashboard/layout.tsx:28,69`) vs. DESIGN.md's documented `paper: #fbf8f3` — likely copy-paste drift, and the CLI detector's color-matcher missed this one (only caught the `rgba()` on line 80), worth noting as a detector coverage gap for future runs.
- `transition-all` (rather than a scoped `transition-transform, box-shadow`) is used on every hover-lift card — functionally fine at this scale, but it's what makes the misapplied-lift issue above (P1) visually loud rather than subtle.
- The three-dot dropdown menu panel uses `shadow-lg` while open — a floating popover, not a resting card, so it doesn't violate the Earned-Shadow Rule as written, but DESIGN.md doesn't explicitly cover popover elevation either; worth adding a line to DESIGN.md if this pattern recurs.
- 600ms entrance stagger (`fadeInUp_0.6s`) and the 2.4s severe-alert pulse are both explicitly intentional per DESIGN.md, not drift — flagged by the raw grep but verified as correct, documented behavior.
